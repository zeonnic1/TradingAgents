# 交易系统理解与策略实现说明

本文档记录 `strategys` 目录下策略代码对应的交易系统理解，用于后续维护和扩展。

## 核心原则

策略层只负责回答一个问题：当前行情是否满足交易系统定义的条件。

策略层不负责：

- 是否开启真实交易
- 下单金额是否大于 0
- 账户余额是否充足
- API key 是否有效
- 是否实际创建订单

这些属于任务执行层、交易所适配层和风控执行层。这样可以保证策略可以独立回测、独立复盘，也可以被 LLM 或人工复核重复调用。

## Trading Hub 流程理解

当前策略来自 `基础概念.md`、`trading hub 3.0.md`、`韦加斯通道.md` 的整理。

标准流程：

1. 建立方向偏见：通过高低点、收盘位置、Vegas EMA144/EMA169 等判断多空背景。
2. 等待外部流动性被掠夺：价格扫过区间高点或低点后重新收回区间。
3. 确认低周期结构转变：扫流动性后出现 CHOCH/BOS，说明市场意图发生变化。
4. 寻找 POI：用 FVG、OB、未缓解区域或扫流动性后的回调区域作为入场候选。
5. 目标指向对侧流动性：止盈优先看区间另一侧、前高前低、EQH/EQL 等流动性位置。
6. 无明确 sweep + CHOCH 时保持 `hold`，不强行交易。

## 当前代码映射

- `base.py`
  - 定义 `BaseStrategy` 抽象类。
  - 定义 `StrategyContext`，只携带策略需要的行情数据。

- `trading_hub.py`
  - 实现 `TradingHubStrategy`。
  - 负责计算 liquidity sweep、CHOCH、Vegas bias、EMA50 bias。
  - 输出 `TradingHubAnalysis`，包含 action、confidence、entry、stop_loss、take_profit、reasons、metadata。

- `factory.py`
  - 定义 `StrategyFactory`。
  - 通过策略名称创建策略实例，避免 Service/Worker 直接依赖具体策略类。

- `strategy.py`
  - 保留兼容函数 `analyze_trading_hub_setup(candles)`。
  - 内部通过 `StrategyFactory` 调用 `TradingHubStrategy`。

## 状态与下单关系

策略输出：

- `buy`：策略满足多头条件。
- `sell`：策略满足空头条件。
- `hold`：策略未满足，任务继续保持 `PENDING` 并轮询。

任务执行层再判断：

- `transaction` 是否开启。
- `amount` 是否大于 0。
- `use_llm_decision` 是否要求 LLM 批准。
- LLM 是否批准且 action 是否仍是 buy/sell。

只有策略满足且执行条件满足时，任务才创建订单并从 `PENDING` 进入 `ORDERED`。

## 合约金额语义

前端和后端的 `amount` 表示 USDT 合约保证金金额，不是基础币数量。

真实提交给交易所的数量由交易所适配层换算：

```text
contract_amount = amount_usdt * leverage / mark_price
```

例如：

```text
amount = 50 USDT
leverage = 10
mark_price = 100
contract_amount = 5
```

订单 `raw_order.info` 会保存：

- `amount_unit = USDT`
- `margin_usdt`
- `notional_usdt`
- `contract_amount`

## 扩展新策略的规则

新增策略时按生产模式处理：

1. 新建策略类并继承 `BaseStrategy`。
2. 实现 `analyze(context: StrategyContext)`。
3. 在 `StrategyFactory` 中注册。
4. 不在策略类里调用交易所下单接口。
5. 不在策略类里读取账户、API key 或任务状态。
6. 策略未满足时必须给出明确 `reasons`，便于任务日志和前端展示。

## 当前保守实现边界

当前 `TradingHubStrategy` 是规则化的保守版本，已覆盖：

- 外部流动性 sweep
- LTF CHOCH
- Vegas EMA144/EMA169 背景
- EMA50 辅助方向
- EMA12 短线确认
- entry、stop、TP1、TP2 的基础推导

后续可继续补充：

- HTF/LTF 多周期显式组合
- FVG / OB / 未缓解区域识别
- EQH / EQL 流动性池识别
- 交易时段过滤
- POI 回踩确认
- 更细的无效条件和风险过滤
